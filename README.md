Я занимаюсь ручным тестированием и автоматизацией (автотесты на API, UI, комбинированные сценарии). Люблю делать мир менее раздражающим и более удобным (и да, даже маленькое исправление бага может сильно влиять на пользовательский опыт).  

## Чем занимаюсь

- Ручное тестирование: чек‑листы, тест‑кейсы, валидация полей, применяю техники тест-дизайна.
- Работа с требованиями: матрица покрытия, критерии выхода.
- Работа с тестовой документацией: составление, корректировка, уточнение, актуализация кейсов для наборов смоук и регресса, статусы баг‑репортов.
- API‑тестирование: сценарии, коды ответов, обработка ошибок.
- Веб‑тестирование: проверка UI и логики в браузере.
- Проверка соответствия UI макетам: состояния элементов, тексты, адаптивность.
- Автоматизация: unit-тесты, мок-тесты, автотесты на API (Java + RestAssured) и UI (Selenium WebDriver), комбинированные сценарии UI + API.

## Навыки и стек

- **Ручное тестирование:**
  - Документация: тест‑планы, матрица покрытия требований, критерии выхода, статусы дефектов, техники тест-дизайна: [КЭ и ГЗ, попарное тестирование, таблица и дерево принятия решений, таблица состояний и переходов (демонстрационный кейс в Google Sheets)](https://docs.google.com/spreadsheets/d/1N9XMTMpapyrw0rBIho9CnJjvKPhrTc2lVRB_0W4wgrA/edit?gid=0#gid=0), баг‑репорты с шагами, предусловиями, тестовыми данными, окружением; приоритизация и согласование с командой.
  - Документация к API: работа со Swagger: чтение спецификаций, проверка соответствия реализации требованиям, поиск расхождений между документацией и реальным поведением API.
  - HTTP/REST API: GET/POST/PUT/PATCH, коды состояния, сценарии валидации и обработки ошибок; проверка бизнес‑логики и граничных условий с учетом требований и классического поведения REST API.
  - SQL: базовые выборки, JOIN, агрегации.
  - Чтение логов 
- **Автоматизация тестирования:**
  - Java 11 — язык автотестов.
  - Maven — сборка проекта, управление зависимостями, запуск тестов (`mvn test`).
  - JUnit4 — параметризация тестов, изоляция через `@After`.
  - RestAssured — автотесты к API.
  - Selenium WebDriver — UI‑автотесты.
  - Библиотеки для оптимизации кода: Lombok, softAssert, Apache HttpClient.
  - Allure и Jacoco — формирование отчётов о прогонах и покрытии.
  - Mockito — моки классов в unit‑тестах.
  - WireMock — мок‑сервер: [использовала для формирования "скелета" автотестов в условиях отключенных серверов](https://github.com/motherOfDragonflys/StellarBurgers_Allure-APITests).
    
- **Инструменты:**
  - Postman — для тестирования API, переменные, проверки ответов.
  - DevTools — анализ сетевых запросов и ответов (методы, коды, заголовки, тела запросов/ответов), проверка верстки и адаптивности через эмуляцию устройств.
  - IDEA — автотесты к API, unit‑тесты, UI‑автотесты и параметризация.
  - Git — ветки, коммиты, пуш, пулл‑реквесты.
  - GitHub Actions — CI-пайплайны для автотестов: триггеры (ручной запуск, cron), контроль статусов раннов.
  - Docker — запуск тестовых стендов и наполнение БД.
  - Android Studio — работа с эмуляторами, установка сборок; adb (logcat, shell) — снятие логов с устройства, поиск ошибок по тегам и стектрейсам для локализации дефектов.
  - Charles — перехват HTTP(S)‑трафика: анализ запросов/ответов, поиск причин дефектов на уровне сети.
  - Kibana — анализ логов на стендах для локализации дефектов.
  - Figma — разбор макетов при тест‑анализе: сверка реализации с дизайном, проверка состояний элементов (обычное, нажатое, ошибка, пустые данные).
  - **AI-инструменты:** ChatGPT и GitHub Copilot — генерация и ревью тест-кейсов, помощь с выявлением серых зон в блоках требований, помощь с SQL-запросами и Java-кодом для автотестов, разбор ошибок и логов. Результаты проверяю и адаптирую под задачу, а не беру «как есть».

### Учебный проект — ЯМаршруты (транспорт: свой автомобиль)  
[Google Sheets](https://docs.google.com/spreadsheets/d/1vJrl1nrgt5S5qXMDpz8wvPdOAMvr5Pt3-6KoPyf1wpU/edit?gid=1610041137#gid=1610041137)  
[GitHub](https://github.com/motherOfDragonflys/yaroutes-manual-testing)  
- Проведен тест‑анализ требований: декомпозиция полей формы на классы и условия (время, адреса, интервалы начала поездки), уточнены серые зоны.
- Применены техники классов эквивалентности и граничных значений — 67 тест‑кейсов на валидацию полей и логику расчёта времени и стоимости поездки.
- Прогон: 41 Passed / 26 Failed, по проваленным кейсам оформлено 16 баг‑репортов (2 блокирующих, 5 средних, 9 низких) с трассировкой «кейс → баг».
- Блокирующие дефекты расчёта не позволили выпустить функцию — итоги оформлены как решение по релизу, а не как перечисление дефектов.

### Учебный проект — Мобильное приложение ЯМетро    
[Google Sheets](https://docs.google.com/spreadsheets/d/1kEIImN4ly2LkltAVgWvFSs6HRjRfgj2g8WbCm9kxG4U/edit?gid=1165888362#gid=1165888362)  
[GitHub](https://github.com/motherOfDragonflys/yametro-manual-testing)  
- Декомпозиция требований, чек-листы фича- и регресс-тестирования (69 тестов), прогон на Android 9.0 (эмулятор Honor 8).
- 15 баг-репортов (10 средних, 5 низких), два бага заблокировали часть прогона — корректно оформлено как Blocked, а не «дефектов не найдено».
- Трассировка «требование → тест → баг» и матрица покрытия к релизу: через трассировку найден пробел в покрытии (смена темы в другом часовом поясе).  
- Решения по релизу: риски по блокам, план доработок.

## Проекты автоматизации

Автотесты к API и UI на Java (RestAssured, Selenium WebDriver, JUnit, WireMock, Allure). Репозитории обновляются — текущие примеры так же в профиле.
### UI тесты
### *Учебный проект — веб-приложение ЯСамокат: [GitHub](https://github.com/motherOfDragonflys/YAScooter_UITests)*  
- Использованы PageObjects и [утилиты для чтения json с эталонами и тестовыми данными](https://github.com/motherOfDragonflys/YAScooter_UITests/tree/main/src/main/java/utils).
- Разработаны масштабируемые и устойчивые к небольшим изменениям dom-структуры автотесты на соответствие ответов и вопросов раздела FAQ, применение json с эталонами ответов.
- Разработан параметризованный автотест на позитивный флоу заказа самоката (отработаны 2 точки входа + по 2 набора тестовых данных для каждой их 2х форм).

### *Учебный проект — веб-приложение Stellar-Burgers: [GitHub](https://github.com/motherOfDragonflys/StellarBurgers_Allure-UITests)* 
- Использованы POJO, PageObjects с локаторами веб-элементов, применены принципы ООП.
- Применен BrowserFactory для быстрого прогона тестов в 2х окружениях.
- Разработаны комбинированные автотесты (UI + API) на сценарии входа из разных точек веб-приложения, параметризованные автотесты позитивного и негативного сценария регистрации, отображения вкладок конструктора.
- Для отчетности использован Allure.

### API тесты
### *Учебный проект — веб-приложение ЯСамокат: [GitHub](https://github.com/motherOfDragonflys/YAScooter_Allure-APITests)*  
- Применена библиотека JavaFaker для генерации неповторяющихся тестовых данных, библиотека Lombok для оптимизации кода в  DTO.
- Соблюдается изоляция тестов, разработан teardown на удаление тестовых пользователей для каждого теста.
- Разработаны тесты на проверку эндпоинтов логина курьера, регистрации курьера, принятия заказа с вынесением общей логики в `@Before` и создания заказа с применением параметризации.
- Для тестов используются отчеты Allure с понятными `@DisplayName`, `@Description` и `@Step`  и группировкой по `@Epic` и `@Feature`.

### *Учебный проект — веб-приложение Stellar-Burgers: [GitHub](https://github.com/motherOfDragonflys/StellarBurgers_Allure-APITests)*  
- Применена библиотека WireMock для стабов ответов сервера, с Javadoc описаны действия для прогона на живом тестовом стенде.
- Разработаны тесты на проверку эндпоинтов создания и регистрации пользователя, создания заказа без использования параметризации для наглядности отчетов.
- Для тестов используются отчеты Allure с понятными `@DisplayName`, `@Description` и `@Step`  и группировкой по `@Feature`.
