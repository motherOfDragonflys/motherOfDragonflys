Я занимаюсь ручным тестированием и автоматизацией: пишу автотесты на API и UI, в том числе комбинированные сценарии, где проверка интерфейса дополняется сверкой с данными из API. Люблю делать мир менее раздражающим и более удобным (и да, даже маленькое исправление бага может сильно влиять на пользовательский опыт).

## Чем занимаюсь

- Ручное тестирование: чек‑листы, тест‑кейсы, исследовательское тестирование.
- Валидация полей: длина, граничные значения, невалидные символы, форматы.
- Работа с требованиями: матрица покрытия, критерии выхода, статусы баг‑репортов.
- Работа с тестовой документацией: составление, корректировка, актуализация кейсов для наборов смоук и регресса.
- API‑тестирование: сценарии, коды ответов, обработка ошибок.
- Веб‑тестирование: проверка UI и логики в браузере.
- Проверка соответствия UI макетам: состояния элементов, тексты, адаптивность.
- Автоматизация: unit-тесты, автотесты на API (Java + RestAssured) и UI (Selenium WebDriver), комбинированные сценарии UI + API.

## Навыки и стек

- **Тестирование:** тест‑планы, матрица покрытия требований, исследовательское тестирование, критерии выхода, статусы дефектов, техники тест-дизайна: [демонстрационный кейс в Google Sheets](https://docs.google.com/spreadsheets/d/1N9XMTMpapyrw0rBIho9CnJjvKPhrTc2lVRB_0W4wgrA/edit?gid=0#gid=0).
- **HTTP/REST API:** GET/POST/PUT/PATCH, коды состояния (2xx, 4xx, 5xx), сценарии валидации и обработки ошибок; проверка бизнес‑логики и граничных условий.
- **Документация API:** работа со Swagger/OpenAPI: чтение спецификаций, проверка соответствия реализации требованиям, поиск расхождений между документацией и реальным поведением API.
- **SQL:** базовые выборки, JOIN, агрегации.
- **Документирование дефектов:** баг‑репорты с шагами, предусловиями, тестовыми данными, окружением; приоритизация и согласование с командой.
- **AI-инструменты:** ChatGPT и GitHub Copilot — генерация и ревью тест-кейсов, помощь с выявлением серых зон в блоках требований, помощь с SQL-запросами и Java-кодом для автотестов, разбор ошибок и логов. Результаты проверяю и адаптирую под задачу, а не беру «как есть».
- **Автоматизация:**
  - Java — язык автотестов.
  - RestAssured — автотесты к API.
  - Selenium WebDriver — UI‑автотесты.
  - Комбинированные сценарии: шаги UI + обращения к API в одном тесте (сверка данных интерфейса с ответами API, подготовка тестового состояния через запросы).
  - JUnit — параметризация тестов, изоляция через `@After`.
  - Maven — сборка проекта, управление зависимостями, запуск тестов (`mvn test`).
  - Allure и Jacoco — формирование отчётов о прогонах и покрытии.
  - Mockito — моки классов в unit‑тестах.
  - WireMock — мок‑сервер: подмена ответов внешних сервисов для проверки граничных случаев и кодов ответов.
  - Тестовые данные — подготовка наборов для позитивных и негативных сценариев и параметризации.

- **Инструменты:**
  - Postman — сценарии, коллекции, переменные, проверки ответов.
  - DevTools — анализ сетевых запросов и ответов (методы, коды, заголовки, тела запросов/ответов), отладка фронтенд‑ошибок в консоли, проверка верстки и адаптивности через эмуляцию устройств.
  - IDEA — автотесты к API, unit‑тесты, UI‑автотесты и параметризация.
  - Git — ветки, коммиты, пуш, пулл‑реквесты.
  - GitHub Actions — CI-пайплайны для автотестов: триггеры (ручной запуск, cron), контроль статусов раннов.
  - Docker — запуск тестовых стендов и наполнение БД.
  - Android Studio — работа с эмуляторами, установка сборок; adb (logcat, shell) — снятие логов с устройства, поиск ошибок по тегам и стектрейсам для локализации дефектов.
  - Charles — перехват HTTP(S)‑трафика: анализ запросов/ответов, поиск причин дефектов на уровне сети.
  - Kibana — анализ логов на стендах для локализации дефектов.
  - Figma — разбор макетов при тест‑анализе: сверка реализации с дизайном, проверка состояний элементов (обычное, нажатое, ошибка, пустые данные).

### [ЯМаршруты (свой автомобиль)]  
[Google Sheets](https://docs.google.com/spreadsheets/d/1vJrl1nrgt5S5qXMDpz8wvPdOAMvr5Pt3-6KoPyf1wpU/edit?gid=1610041137#gid=1610041137)  
[GitHub](https://github.com/motherOfDragonflys/yaroutes-manual-testing)  
- Проведен тест‑анализ требований: декомпозиция полей формы на классы и условия (время, адреса, интервалы начала поездки), уточнены серые зоны
- Применены техники классов эквивалентности и граничных значений — 67 тест‑кейсов на валидацию полей и логику расчёта времени и стоимости поездки
- Прогон: 41 Passed / 26 Failed, по проваленным кейсам оформлено 16 баг‑репортов (2 блокирующих, 5 средних, 9 низких) с трассировкой «кейс → баг»
- Блокирующие дефекты расчёта не позволили выпустить функцию — итоги оформлены как решение по релизу, а не как перечисление дефектов

### Мобильное приложение «ЯМетро»    
[Google Sheets](https://docs.google.com/spreadsheets/d/1kEIImN4ly2LkltAVgWvFSs6HRjRfgj2g8WbCm9kxG4U/edit?gid=1165888362#gid=1165888362)  
[GitHub](https://github.com/motherOfDragonflys/yametro-manual-testing)  
- Декомпозиция требований, чек-листы фича- и регресс-тестирования (69 тестов), прогон на Android 9.0 (эмулятор Honor 8)
- 15 баг-репортов (10 средних, 5 низких), два бага заблокировали часть прогона — корректно оформлено как Blocked, а не «дефектов не найдено»
- Трассировка «требование → тест → баг» и матрица покрытия к релизу: через трассировку найден пробел в покрытии (смена темы в другом часовом поясе)  
- Решения по релизу: риски по блокам, план доработок
